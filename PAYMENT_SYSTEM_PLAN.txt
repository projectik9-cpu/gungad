1. ЦЕЛЬ
═══════════════════════════════════════════════════════════════

Сделать автоматическое пополнение баланса в казино без ручной
проверки каждого платежа, с надёжным учётом денег в базе и
безопасным выводом.

Пользователь платит → сервер получает подтверждение → баланс
начисляется сам.


═══════════════════════════════════════════════════════════════
2. ЧТО УЖЕ ЕСТЬ СЕЙЧАС
═══════════════════════════════════════════════════════════════

• Баланс хранится в базе Supabase (таблица gg_wallets).
• Деньги учитываются в центах USD (100 = $1.00) — без «плавающей»
  арифметики, чтобы не было ошибок округления.
• Каждое движение денег пишется в журнал (gg_ledger): ставка,
  выигрыш, пополнение, вывод.
• Ставки проходят через сервер (gg_settle_bet) — клиент сам себе
  баланс не меняет в реальном режиме.

То есть «кошелёк» внутри казино уже готов. Нужно подключить
внешние способы оплаты.

3. РЕКОМЕНДУЕМАЯ СХЕМА (ИТОГ)
═══════════════════════════════════════════════════════════════

✅ Crypto Bot Pay — для тех, кому удобно платить через @CryptoBot
   в Telegram (USDT / TON / BTC и др. внутри бота).

✅ Tonkeeper (TON) — для прямых переводов с кошелька.

✅ Оба способа автоматически начисляют баланс на сервере
   после подтверждения платежа.

✅ Вывод средств — вручную с холодного кошелька Tonkeeper
   (на старте безопаснее и проще для контроля).


═══════════════════════════════════════════════════════════════
4. СПОСОБ 1 — Crypto Bot Pay (основной, самый простой)
═══════════════════════════════════════════════════════════════

Что это:
  Официальный платёжный сервис Telegram Crypto Bot.
  Пользователь платит внутри Telegram, нам приходит webhook.

Схема работы:

  1) Пользователь нажимает «Пополнить» в GunGad.
  2) Наш сервер создаёт счёт (invoice) через API Crypto Bot
     на нужную сумму и валюту.
  3) Пользователю открывается оплата в Crypto Bot.
  4) После успешной оплаты Crypto Bot шлёт webhook на наш сервер
     (HTTPS-endpoint на Railway).
  5) Сервер проверяет подпись webhook, находит пользователя
     по invoice / payload (profile_id).
  6) Сервер атомарно начисляет balance_cents в gg_wallets
     и пишет запись в gg_ledger (kind = deposit / star_topup).
  7) Пользователь сразу видит новый баланс в мини-приложении.

Плюсы:
  • почти без ручной работы;
  • привычно для аудитории Telegram;
  • меньше риска ошибиться с адресами кошельков;
  • легко логировать и аудировать платежи.

Минусы:
  • комиссия Crypto Bot;
  • зависимость от стороннего сервиса.

5. СПОСОБ 2 — Tonkeeper / прямые TON-переводы
═══════════════════════════════════════════════════════════════

Что это:
  Пользователь переводит TON (или jetton, если решим позже)
  со своего кошелька Tonkeeper на наш адрес.

Два рабочих подхода:

  A) Отдельный депозитный адрес на пользователя
     — сервер видит поступление на «его» адрес и сразу знает,
       кому начислить.
     Плюс: просто и надёжно идентифицировать плательщика.
     Минус: сложнее инфраструктура адресов / ключей.

  B) Один общий адрес + уникальный комментарий (memo / payload)
     — при создании депозита сервер выдаёт уникальный код
       (например gg_dep_<profile_id>_<id>).
     Пользователь обязан указать этот комментарий в переводе.
     Сервер следит за входящими транзакциями в блокчейне TON
     и по комментарию понимает, кому зачислить.

  Для старта разумнее вариант B (один адрес + комментарий):
  быстрее внедрить и проще операционно.

Схема работы (вариант B):

  1) Пользователь выбирает «Пополнить через TON».
  2) Сервер создаёт заявку на депозит: сумма, уникальный
     комментарий, статус pending.
  3) UI показывает адрес кошелька + комментарий + сумму.
  4) Фоновый воркер / webhook-индексатор смотрит входящие
     транзакции на наш адрес.
  5) При совпадении суммы (или ≥ суммы) + комментария
     и после N подтверждений в сети:
       • статус заявки → paid;
       • баланс начисляется в gg_wallets;
       • пишется gg_ledger.
  6) Если комментарий неверный / сумма неверная — деньги
     не зачисляются автоматически (ручной разбор / саппорт).

Плюсы:
  • прямой перевод «с кошелька на кошелёк»;
  • не зависит от Crypto Bot;
  • удобно для пользователей TON.

Минусы:
  • нужно мониторить блокчейн;
  • риск ошибки пользователя (забыл комментарий);
  • нужна чёткая инструкция в UI.

6. КАК ХРАНИТСЯ БАЛАНС (ВНУТРЕННЯЯ ЛОГИКА)
═══════════════════════════════════════════════════════════════

• Баланс живёт только на сервере (Supabase), не в localStorage.
• Пополнение = запись в ledger + увеличение balance_cents.
• Ставка = атомарное списание/начисление через RPC
  (защита от двойных списаний и гонок).
• История платежей и ставок сохраняется и доступна в профиле.
• Демо-режим отделён от реального баланса (не путаем).

Важно:
  Клиент (мини-приложение) НИКОГДА не является источником
  истины по деньгам. Он только показывает то, что вернул сервер.

7. ВЫВОД СРЕДСТВ (НА СТАРТЕ)
═══════════════════════════════════════════════════════════════

Рекомендация на запуск:

  • Пользователь создаёт заявку на вывод (сумма + адрес TON).
  • Сервер проверяет баланс, «замораживает» сумму (locked_cents).
  • Заявка уходит в очередь админу / оператору.
  • Выплата делается вручную с холодного кошелька Tonkeeper.
  • После отправки оператор отмечает заявку paid → ledger
    фиксирует вывод.

Почему вручную сначала:
  • меньше риска багов с авто-выводом;
  • контроль антифрода;
  • проще бухгалтерия на старте.

Позже можно добавить полуавтомат / авто-вывод с лимитами.

8. БЕЗОПАСНОСТЬ
═══════════════════════════════════════════════════════════════

• Webhook Crypto Bot — проверка подписи.
• Депозиты TON — только после подтверждений в сети.
• Идемпотентность: один и тот же платёж не начислит баланс дважды
  (уникальный payment_id / tx hash в базе).
• Service role ключи только на сервере (Railway), не во фронте.
• Админские действия по выводу — только у доверенных лиц.
• Холодный кошелёк для хранения основной кассы.

10. КРАТКИЙ ВЫВОД ДЛЯ РУКОВОДСТВА
═══════════════════════════════════════════════════════════════

Мы предлагаем принимать депозиты двумя каналами:

  1) Crypto Bot Pay — проще всего, полностью автоматически.
  2) Tonkeeper / TON — прямые переводы, тоже с авто-зачислением
     после проверки блокчейна.

Баланс игрока хранится в нашей базе (центы USD), все движения
логируются. Вывод на старте — вручную с холодного кошелька,
чтобы не рисковать кассой.

Такая схема удобна игрокам, снижает ручную работу по депозитам
и даёт контроль над выводом.
